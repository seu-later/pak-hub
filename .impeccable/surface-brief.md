# Pak Hub catalog surface

## Mode

Operate. Players search and scan the public mod archive, then choose a release and file variant.

## Approved composition

The user selected Composition B, Archive ledger, in response to the three-layout review. Approved north-star comp: `.impeccable/mocks/02-archive-ledger.png`.

## Direction contract

- **World:** DRG-inspired mine-operations terminal, with White Rabbit on the wordmark and short display labels; readable sans-serif for paragraphs and long catalog rows.
- **First viewport:** A compact Pak Hub navigation bar, archive heading and search, category controls, then a full-width mod ledger with aligned fields for name, category, creator, release, and date. The selected mod expands inline beneath its own row and shows release history, pak variants, and a download action.
- **Visitor path:** Search or filter the ledger; open a mod row; select a release and one of its pak variants; follow the direct public GitHub release-asset URL.
- **Signature interaction:** Expanding a selected ledger row reveals its release dossier in place, keeping the archive context visible. Selecting a release updates its file variants and download target.
- **System rules:** Coal-dark slate surfaces, muted metal neutrals, amber hazard-yellow for selected/action states, restrained mineral teal for data labels, and fine dividers. Use native web inputs, buttons, rows, and selects. Avoid simulated terminal command entry.
- **Honest risk:** An expanded history pushes later rows down the page; mobile collapses the ledger to name/category/release and retains the inline dossier below the selected row.

Demo rows are synthetic and visibly labeled; their download actions remain disabled. Production empty/error states must say whether the live catalog is empty or unavailable.
